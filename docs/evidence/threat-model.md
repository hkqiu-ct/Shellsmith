# Shellsmith 威胁模型（证据基线）

状态：`baseline`。本文定义攻击者、资产、信任边界和成功标准；具体实验结果见 `experiment-matrix.md` 与两条链的报告。

## 1. 资产

| 资产 | 位置 | 价值 |
|---|---|---|
| 业务 DEX / PVM2 镜像 | APK、运行时内存、私有缓存 | 代码语义、算法、密钥流程 |
| 业务 SO | APK、运行时私有目录 | Native 算法与协议 |
| 路由索引 | `.rtap` / 旧 `.txt` | 页面、服务、参数注入路径 |
| 产物 IKM | 离线 DEXB v6 包内材料；BYOS 服务端 | 派生载荷密钥 |
| 设备密钥 | Android Keystore / iOS Keychain | 设备批准、签名证明 |
| Play Integrity token | 运行时获取，服务端校验 | 应用/设备状态证明 |
| 构建 API key | 构建机与服务端 | 产物注册 |
| 服务端主密钥 / KMS / HSM | 服务端或云 KMS/HSM | 封存/解封 IKM |
| 签名证书与发布密钥 | 构建机、CI、更新清单 | 产物可信与更新链 |

## 2. 攻击者模型

| 模型 | 能力 | 目标 | 成功标准 |
|---|---|---|---|
| A1 仅 APK | 静态分析、重打包、模拟器 | 恢复业务 DEX/关键方法、绕过签名绑定 | 能稳定恢复并运行等价业务代码 |
| A2 已授权设备 | 安装、调试、Frida、内存 dump、Root/越狱 | 提取 IKM、明文 DEX/SO、绕过 RASP | 能提取可复用秘密或代码 |
| A3 服务端/供应链 | 改服务端、数据库、KMS/HSM、CI | 解封 IKM、伪造授权、替换产物 | 能绕过授权或替换发布物 |
| A4 网络 | 中间人、重放、转发 | 获取 IKM、伪造响应 | 能重复取钥或解密响应 |

## 3. 信任边界

1. APK 边界：包内材料是否足以恢复载荷。
2. 设备边界：Keystore/Keychain、私有目录、进程内存。
3. 服务端边界：TLS 终止、数据库、KMS/HSM、审计。
4. 分发边界：上传证书、Play App Signing、更新清单。
5. 构建边界：源码、依赖、CI 凭据、签名材料。

## 4. 成功与失败

**成功**不是“应用能启动”，而是：

- 必保方法 100% 通过最终产物核验。
- 原包/加固包在选定业务路径上语义等价。
- 负面测试在预期层拒绝。
- 运行时明文窗口和密钥暴露有测量数据。
- 第三方能按脚本复现关键结果。

**失败**包括：

- 工具报错、字节变化、文件哈希变化被当作保护有效。
- 只在一台设备/一个样本上通过，却外推到全部平台。
- 外部验证缺失却写成“已解决”。

## 5. 明确边界

- DEXB v6 不提供针对静态分析的机密性。
- BYOS 不阻止已授权进程的内存提取。
- 客户端完整性检查不能替代服务端鉴权。
- 单设备 IKM 泄漏需要 per-device payload 才能阻断，当前不排期。
